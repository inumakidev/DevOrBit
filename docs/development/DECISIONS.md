### Trust-policy parsing contract approval

The user approved the strict trust-policy parsing contract and its caller-specific resource limits. This records that approval and does not claim implementation. The normative schema and detailed limits are in [the canonical registry and resolver architecture](../main/11-registry-and-resolver-architecture.md), §6.

Approved policy parsing requirements include: exact top-level and nested field sets; strict UTF-8 JSON; rejection of BOM, malformed UTF-8, duplicate decoded keys, unknown/missing fields, and invalid types; acceptance of valid JSON whitespace/property-order variations; and policy digest calculation over RFC 8785 canonical UTF-8 bytes. Policy IDs must already be lowercase canonical repository IDs without changing M1 behavior. Public keys use canonical unpadded base64url for exactly 32 raw bytes with matching SHA-256 key IDs. Required arrays are sorted and unique; signer scopes are subsets of policy repositories. Timestamps use exact Gregorian UTC `YYYY-MM-DDTHH:mm:ss.sssZ`, years 0001–9999, exact 720-hour policy lifetime, and nonempty signer half-open intervals contained in the policy interval. Expiry relative to current time is not a parser rejection condition. Sequence accepts exact positive safe-integer JSON numeric values, including equivalent decimal/exponent syntax; values that are fractional mathematically are rejected even if binary64 conversion rounds them to integers.

Approved inclusive policy-caller limits: raw policy input 1 MiB; canonical JCS policy output 1 MiB; repositories, authorized signers, repository IDs per signer, revoked signer IDs, and revoked repository IDs each at most 10,000 (collection ceilings additionally constrained by raw bytes). The future raw signed-update envelope ceiling is 2 MiB; this does not authorize update parsing or verification. Policy JCS caller budget: depth 64; 1,000,000 JSON values; 10,000 properties per object; 1 MiB per string; 1 MiB cumulative string/key bytes; 1 MiB output. Parser key counting, if used, is a separate explicitly documented budget and must not silently exclude policies allowed by these constraints. These are policy-caller limits, not global JCS defaults. The approved complete-snapshot canonical-byte limit remains 64 MiB, unchanged.

The approved parser boundary excludes administrator authentication, signed-update or chain verification, signer/repository authorization, revocation effects, protected state, filesystem/Git/network access, registry discovery, and resolver behavior. The implementation does not perform those operations.
